会话与上下文 ​

nek 把一段对话保存为一个会话。会话里的消息组成一棵树，当前所在的那条路径（活动分支）就是下一次请求发给模型的历史。这一页讲怎么续接会话、怎么分支尝试另一种做法，以及怎么控制发给模型的上下文大小。

续接与切换会话 ​

会话默认自动保存（用 --no-session 启动时除外）。

bash
nek -c          # --continue：继续当前目录最近的会话
nek -r          # --resume：打开会话列表选择
nek -c "上次说到哪了？"   # 继续并立即发送一条消息

在 nek 里：

命令作用
/resume打开会话列表，切换到别的会话
/new开始新会话
/name <名字>设置会话显示名（不带参数时显示当前名字）。也可以启动时用 -n "名字"
/session查看会话文件路径、ID、消息数、token 用量和费用

会话列表 ​

/resume 和 nek -r 打开的列表支持搜索，以及这些快捷键：

按键作用
输入文字搜索
Ctrl+P显示/隐藏会话所在路径
Ctrl+S切换排序方式
Ctrl+N只看起过名字的会话
Ctrl+R重命名选中的会话
Ctrl+D删除选中的会话（需确认；有 trash 命令时移到回收站）
Ctrl+Backspace搜索框为空时删除选中的会话

按路径或 ID 打开 ​

bash
nek --session <路径或ID>     # 按文件路径、完整 ID 或 ID 前缀打开
nek --session-id my-task     # 打开当前项目里 ID 为 my-task 的会话，不存在就创建
nek --fork <路径或ID>        # 把已有会话复制成当前项目的一个新会话

--session 先在当前项目里查找；匹配到其他项目的会话时，会提示你复制（fork）一份到当前项目。会话 ID 只能包含字母、数字、.、_、-，且首尾必须是字母或数字。

分支：换一条路线试试 ​

会话以树的形式存储，回到较早的某一点继续，不会抹掉你离开的那条分支。

操作结果适合
/tree在当前会话内移动到任意一个节点，从那里继续相关的多种尝试放在一起
/fork选一条较早的用户消息，从它开始创建一个新会话另一种做法应该成为独立的工作
/clone把当前活动分支原样复制成一个新会话想要一份当前状态的独立副本

输入框为空时连按两次 Escape，默认打开 /tree（设置 doubleEscapeAction 可改为 fork 或 none）。

会话树 /tree ​

/tree 以树状显示整个会话，选中一个节点后按 Enter 跳过去。常用按键：

按键作用
Ctrl+← / Alt+←折叠当前分支段，或跳到上一段的开头
Ctrl+→ / Alt+→展开当前分支段，或跳到下一段的开头/分支末尾
Shift+L给选中的节点加标签（书签）
Shift+T显示/隐藏标签的时间
Ctrl+D过滤器：默认视图
Ctrl+T过滤器：隐藏工具结果
Ctrl+U过滤器：只看用户消息
Ctrl+L过滤器：只看带标签的节点
Ctrl+A过滤器：显示全部
Ctrl+O / Shift+Ctrl+O循环切换过滤器
Ctrl+X复制选中的消息

打开时使用的默认过滤器由设置 treeFilterMode 决定。

分支摘要 ​

离开一条分支时，nek 会问你是否为它生成摘要。选择生成的话，模型会把被放弃的那条路径总结一下，附在你进入的新位置上。这样新分支能知道之前试过什么，又不用带上全部消息。

不想每次被问，可以设置 branchSummary.skipPrompt: true（默认不生成摘要）。

控制上下文大小 ​

发给模型的只有活动分支，不是会话里的所有分支。nek 把活动分支和系统提示词、项目指令、工具声明、Skills 描述组合起来，见 nekcode 如何工作。

上下文接近模型上限时，nek 会自动压缩：

  1. 从最新的消息往回数，保留大约 20k token 的近期消息原样不动；
  2. 更早的部分交给模型总结成一份结构化摘要（目标、约束、进度、关键决定、下一步、关键上下文，以及读过和改过的文件）；
  3. 之后的请求用“摘要 + 近期消息”代替完整历史。

原始消息仍然保存在会话里，/tree 和导出都能看到。

操作方式
手动压缩/compact，可以附加说明，例如 /compact 重点保留数据库迁移相关的结论
关闭自动压缩设置 compaction.enabled: false（仍可手动压缩）
调整触发时机和保留量compaction.reserveTokens、compaction.keepRecentTokens
用另一个模型写摘要compaction.model、compaction.thinkingLevel

状态栏的上下文进度条显示当前用量。压缩的触发条件、内容折叠策略和全部设置见 上下文压缩。

会话存储位置 ​

默认存放在 ~/.nek/agent/sessions/ 下，按工作目录分组：

text
~/.nek/agent/sessions/--home-me-project--/2026-10-16T08-00-00-000Z_<会话ID>.sqlite
~/.nek/agent/sessions/--home-me-project--/2026-10-16T08-00-00-000Z_<会话ID>.meta.json
  • .sqlite 是会话数据库；.meta.json 只是 /resume 列表的缓存，丢了会自动重建；
  • 会话打开期间旁边有一个 .lock 文件，同一个会话不能被两个 nek 进程同时打开；
  • 子代理的会话存放在父会话目录下的 subagents/ 里。

改变存储位置（优先级从高到低）：

  1. 启动参数 --session-dir <目录>；
  2. 环境变量 NEK_CODING_AGENT_SESSION_DIR；
  3. 设置 sessionDir（相对路径从工作目录解析）。

其他相关参数：--no-session 使用不落盘的临时会话。

崩溃后续跑 ​

一轮里的每一步都会先写入数据库再继续。nek 被强制结束（崩溃、kill、关掉终端、断电）后，用 nek -c 或 /resume 重新打开会话，中断的那一轮会自动接着跑。哪些工具会重跑、哪些只标记为“已中断”，见 Durable 会话与崩溃续跑。

旧的 JSONL 会话 ​

从 pi 或旧版 nek 带过来的 .jsonl 会话可以直接打开（--session <路径>），或在 nek 里用 /import <路径> 导入。打开时 nek 会生成同名的 .sqlite，原来的 .jsonl 文件保持不变。

删除会话 ​

在 /resume 列表里选中后按 Ctrl+D 并确认；或直接删除 ~/.nek/agent/sessions/ 下对应的 .sqlite 和 .meta.json 文件（以及可能存在的旧 .jsonl 文件）。

导出与分享 ​

命令作用
/export [路径]导出为 HTML（默认）或 JSONL（路径以 .jsonl 结尾）
/share上传并返回查看链接（Radius，或通过 gh 创建私密 gist）
nek --export <会话文件> [输出.html]在命令行导出

导出或分享前请检查内容：会话里可能有提示词、模型回复、工具参数、命令输出、文件内容和扩展消息。
