# Durable 会话与恢复策略

nek 的每一轮都运行在 durable 引擎（`@earendil-works/pi-durable`）上。一轮里的每一步都会先提交到会话数据库，再开始下一步：用户输入、流式文本、每个工具调用和结果、排队的消息、压缩。

## CLI 重开策略

关闭 CLI 后，再用 `nek -c`、`--resume` 或 `/resume` 打开会话，只恢复历史，**不会自动继续上一次 AI 回合**。启动时会终止遗留运行、排队输入和未完成压缩；部分回复保留为已中止，工具不会自动重跑。会话保持空闲，等你显式发送新消息才发起请求。这避免关闭终端后又静默重复模型请求或工具副作用。

CLI 固定使用 `resumeInterruptedWork: false`；SDK 仍默认保留 `resumeInterruptedWork: true` 的崩溃恢复能力。

## 续跑中断的一轮

以下仅适用于保留 `resumeInterruptedWork: true` 的 SDK 会话，**不代表 CLI 重开行为**：

| 中断时正在 | 重新打开后 |
|---|---|
| 模型流式输出 | 已输出的部分作为“已中止”的回复保留在历史里，请求重新发送 |
| 只读工具（`read`、`grep`、`find`、`ls`、`ast_grep`、`web_search`） | 工具重新执行 |
| 其他工具（`bash`、`edit`、`write`、MCP 和扩展工具） | 调用结果保留已有的部分输出并注明“已中断”，这一轮继续；由模型决定是否重新执行。**不会**自动重跑，因为副作用可能已经发生 |
| nek 的协作工具（`ask_question`、`switch_mode`、`todo_write`、`await`、`subagent`、`stop_subagent`） | 重新执行 |
| 前台子代理 | 重新打开**同一个**子会话，让它继续自己中断的那一轮，结果照常返回父会话 |
| 提问框或模式切换确认框 | 重新弹出 |
| 排队的插话或追加消息 | 仍在队列中，按顺序送达 |
| `/compact` | 压缩重新执行 |
| 扩展的 `agent_before_settle` 处理 | 重新执行 |

中断的工作在扩展收到 `session_start` 之后才恢复，保证重跑工具之前扩展的状态已经恢复。

续跑的这一轮在界面上显示为 Working。这时发送的消息和平常一样作为插话排队，在当前工具调用结束后送达；按 `Escape` 可以中止续跑。

扩展工具用 `replay: "safe"` 声明自己可以安全地执行两次；这样的工具可以用 `ctx.getToolCallMemo(toolCallId)` 在两次执行之间保存值（`set()` 保存的值在崩溃后同一调用重跑时由 `get()` 返回）。`subagent` 工具就是用它找回自己启动的子会话。见 [编写扩展](/develop/extensions#tools)。

后台子代理在父会话重开后不会自动接回，在 `resume` 或 `await` 它时才处理。`resume` 一个崩溃时还在运行的子代理时，它先把中断的那一轮跑完，再处理新的提示；这期间子代理显示为运行中，可以 `Escape` 中止，发送新消息时前台等待会转入后台。传 `interrupt: true` 则直接放弃中断的那一轮。

## 输入预检与维护互斥

提示词在异步输入钩子和认证之前就会占用当前上下文。预检期间不能切换会话树、重载或手动压缩；手动压缩、分支摘要和重载正在替换上下文时，也不能提交新的提示词。

预检期间接受的插话和追加消息，会在主输入实际进入 durable 后加入同一次运行，不会抢先自启另一轮。主提示词被钩子处理、认证失败或在启动前取消时，已接受的排队输入保持可见，等下一次显式提示词再送达；SDK 也可用 `clearQueue()` 取回。输入钩子不会重复执行，也不会静默恢复旧运行。

## 存储

每个会话是一个 SQLite 数据库：

```text
<时间戳>_<会话ID>.sqlite      会话数据库
<时间戳>_<会话ID>.meta.json   /resume 列表的缓存，缺失或过期时从数据库重建
<时间戳>_<会话ID>.lock        打开会话的进程持有的锁
```

同一个会话不能被两个进程同时打开。

打开旧的 `.jsonl` 会话时，nek 把它导入同名的 `.sqlite`，`.jsonl` 文件保持不变。见 [会话文件格式](/reference/session-format)。

## 与旧的代理循环的差异

会话 API、事件和扩展钩子没有变化，个别行为有所不同：

- **重试**：一次运行包含它的自动重试，监听器只在最后收到一个 `agent_end`（`willRetry: false`）。每次失败的尝试仍会结束自己的一轮（带错误的 `turn_end`），`auto_retry_start` / `auto_retry_end` 照常发出；
- **流式粒度**：流式文本大约每秒提交十次，所以 `message_update` 事件的步子更大；
- **并行工具**：并行调用的 `tool_execution_end` 按完成顺序到达；
- **请求前中止**：在运行准备第一次请求时中止，不会发出请求，历史里仍会有一个空的已中止回复；
- **系统提示词和工具变化**作为按位置排列的系统条目保存在历史里，请求看到的提示词和工具与之前相同；
- **`session.agent`** 为兼容而保留会话状态（`state`、`transport`），它自己的循环不再运行，`agent.subscribe()` 的监听器会收到这一轮的循环事件并按事件逐个等待；
- **分支**以同一数据库中的分叉对话保存，`/tree`、`/fork` 和分支摘要照常工作。

## 已知限制

- 正常退出后，会话目录里可能残留 `.sqlite-wal` / `.sqlite-shm` 文件，不影响正确性。
- 上游服务卡住但没有断开连接时，nek 无法区分“模型还在思考”和“流已经死了”，要等 `httpIdleTimeoutMs`（默认 5 分钟）才会报错并重试。
