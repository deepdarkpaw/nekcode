# nekcode 如何工作

这一页解释 nek 内部的几个核心概念：代理循环（agent loop）、上下文、会话树、模式和工具。理解它们以后，排队消息、分支、压缩、Plan 模式这些功能的行为就都说得通了。

## 代理循环 {#agent-loop}

你发送一条消息后，nek 做的事情是一个循环：

1. 把你的消息追加到当前分支；
2. 用系统提示词、当前分支的历史、可用工具和模型设置拼出一次模型请求，发给所选服务商；
3. 服务商流式返回助手回复，回复里可以有文字，也可以有**工具调用**；
4. nek 记录回复，执行每个工具调用（同一条回复里的多个调用可以并行），记录结果；
5. 如果有工具结果或排队消息需要模型继续处理，回到第 2 步开始下一**轮（turn）**；否则这次**运行（run）**结束。

一轮 = 一次助手回复 + 它触发的工具调用和结果。一次运行可以包含很多轮。

运行过程中你可以继续输入：

| 消息类型 | 何时送达 | 默认按键 |
|---|---|---|
| 插话（steering） | 当前这一轮的工具执行完之后、下一次模型请求之前 | `Enter` |
| 追加（follow-up） | 整个运行结束、没有其他待办工作之后 | `Alt+Enter`（Windows/WSL 为 `Ctrl+Q`） |

按 `Escape` 中止当前运行，排队中的消息会退回输入框。

### 自动重试

服务商返回过载、限流、5xx、连接中断这类临时错误时，nek 会按 `retry` 设置指数退避自动重试（默认最多 3 次），见 [settings.json](/reference/settings#network)。

## 上下文 {#context}

模型每次看到的内容由这些部分组成：

```text
┌ 系统提示词 ───────────────────────────────┐
│ nek 的身份句 + 基础指令 + 各工具的使用说明    │
│ + Skills 列表（只有名字和描述）               │
│ + APPEND_SYSTEM.md 等追加内容                │
├ 项目指令 ─────────────────────────────────┤
│ AGENTS.md / CLAUDE.md（每次请求都会带上）     │
├ 当前分支的历史 ────────────────────────────┤
│ [压缩摘要] + 用户消息 + 助手回复 + 工具结果 ... │
└──────────────────────────────────────────┘
+ 工具声明（名字、描述、参数 schema）
```

几点说明：

- **项目指令**（`AGENTS.md`）不放在系统提示词里，而是每次请求时在系统消息之后插入一条单独的消息，不写入对话记录。这样在一个会话里，系统提示词和工具声明保持稳定，服务商的提示词缓存不会因为指令变化而整段失效。
- **Skills** 只把名字、描述和路径放进系统提示词；模型判断需要时才读取完整的 `SKILL.md`。
- **提示词模板** 在你的输入变成用户消息之前就展开了。
- 你用 `@` 引用的文件、粘贴的图片、`!` 命令的输出，都会成为消息内容。
- 扩展可以追加指令，或者在发送前改写上下文。

上下文接近模型上限时，nek 会自动**压缩**：把较早的历史总结成一段摘要，保留最近的消息。原始记录仍然保存在会话里。见 [会话与上下文](/guide/sessions#compaction) 和 [上下文压缩](/reference/compaction)。

## 会话与分支 {#sessions}

会话里的每条消息和事件都是一个**条目（entry）**，每个条目有 ID，并指向它的父条目，所以整个会话是一棵**树**：

```text
用户 ─ 助手 ─ 用户 ─ 助手 ─┬─ 用户 ─ 助手        ← 当前分支（活动分支）
                          └─ 分支摘要 ─ 用户     ← 另一个分支
```

- 从树根到当前条目的那条路径叫**活动分支**，它就是下一次请求的历史。
- 用 `/tree` 回到较早的某一点继续，会在同一个会话里长出新分支，原来的分支不会丢。
- `/fork` 和 `/clone` 把选定的历史复制到一个新会话。

持久化的会话是 SQLite 数据库，由 durable 引擎写入：一轮里的每一步（你的输入、流式文本、每个工具调用和结果、排队消息、压缩）都先落盘再继续。所以进程被杀之后重开会话，中断的那一轮会接着跑。见 [Durable 会话与崩溃续跑](/reference/durable-sessions)。

## 模式 {#modes}

nek 有两种工作模式：

| 模式 | 能做什么 | 进入方式 |
|---|---|---|
| Agent（默认） | 读写文件、执行命令，正常完成任务 | 默认；`/agent`；`Alt+M` |
| Plan | 只调研和写计划；`edit`/`write` 只能改 Markdown 文件，子代理只读 | `/plan`；`Alt+M`；`nek --plan` |

Plan 模式写完计划后由你审阅，批准后切换到 Agent 模式实施。模型自己也可以通过 `switch_mode` 工具**提议**切换，但必须由你确认。见 [Plan 模式](/guide/plan-mode)。

## 工具 {#tools}

模型通过工具与外部世界交互。nek 的工具分几类：

| 类别 | 工具 |
|---|---|
| 文件 | `read`、`edit`、`write` |
| 搜索 | `grep`、`find`、`ls`、`ast_grep`、`web_search` |
| 命令 | `bash`（Windows 可选 `powershell`） |
| 规划与协作 | `todo_write`、`switch_mode`、`create_plan`、`update_plan`、`ask_question` |
| 子代理 | `subagent`、`await` |
| 按需加载 | `tool_search`（存在延迟加载的工具时才出现，例如 MCP 工具） |

每个工具的行为见 [内置工具](/guide/tools)。工具以 nek 进程的操作系统权限运行，nek 不提供沙箱。

## 界面与运行方式 {#interfaces}

同一套代理和会话机制有多种使用方式：

| 方式 | 说明 |
|---|---|
| 交互模式 | 默认的终端界面 |
| print 模式 | `nek -p "..."`，执行一次，把最终回复打印到 stdout |
| JSON 模式 | `nek --mode json "..."`，把事件流以 JSONL 写到 stdout |
| RPC 模式 | `nek --mode rpc`，从 stdin 接收 JSONL 命令，长期运行 |
| SDK | 在 Node.js/Bun 程序里直接创建和控制会话 |

见 [脚本与程序集成](/develop/cli-integration)。

## 内置扩展与资源 {#extensions}

nek 的独有功能（Plan、Todo、子代理、提问框）以一个名为 `nek` 的内置扩展实现；MCP、`tool_search`、llama.cpp 服务商也是内置扩展。你自己的扩展可以注册工具、命令、快捷键、服务商、事件处理和界面组件，见 [编写扩展](/develop/extensions)。

其他资源：

- **Skills**：按需加载的专项说明和配套文件；
- **提示词模板**：可复用的消息文本，作为 `/` 命令使用；
- **主题**：终端配色。

## 信任与权限 {#trust}

nek 在加载项目配置和资源之前先决定是否**信任**这个项目。信任只决定加载哪些项目资源，**不是沙箱**：启用的工具始终以 nek 进程的权限运行，扩展也在 nek 进程内执行。处理不可信的代码请使用容器或其他沙箱，见 [安全使用](/guide/security)。
