配置总览 ​

nek 的配置分为用户级和项目级两层：

  • 用户级数据在 ~/.nek/agent/（可用环境变量 NEK_CODING_AGENT_DIR 改变，下文称“agent 目录”），对所有项目生效；
  • 项目级配置在工作目录下的 .nek/，在信任项目之后才加载。例外是 sessionDir，它在决定信任之前就会被读取，以便定位会话。

交互模式下用 /settings 修改常用设置。手动修改设置、快捷键、指令文件或资源之后，运行 /reload 让当前会话生效。

agent 目录（用户级） ​

路径作用
settings.json用户级 设置
nek.yamlnek 独有功能的配置：Plan、Todo、子代理，见 nek.yaml
keybindings.json自定义 快捷键
models.json兼容接口、自定义模型和模型元数据覆盖
auth.json保存的 API key 和 OAuth 凭据（勿外传）
mcp.jsonMCP 服务器
mcp-auth.jsonMCP 服务器的 OAuth 凭据
trust.json保存的 项目信任 决定
AGENTS.md（或 AGENTS.override.md、CLAUDE.md 等）对所有项目生效的 指令
SYSTEM.md替换默认系统提示词（nek 的一句身份说明仍保留在最前面）
APPEND_SYSTEM.md追加到系统提示词末尾
agents/*.md自定义 子代理类型
extensions/自动加载的 扩展
skills/用户级 Skills
prompts/用户级 提示词模板
themes/用户级 主题
sessions/会话存储（可用 sessionDir 等改变，见 会话与上下文）
bin/自动下载的 fd、rg、ast-grep
mcp.logMCP 服务器日志
nek-debug.log/debug 写出的诊断信息

项目 .nek 目录 ​

路径作用
.nek/settings.json项目级设置，覆盖用户级同名设置
.nek/nek.yaml项目级 nek 配置
.nek/mcp.json项目级 MCP 服务器
.nek/agents/*.md项目级子代理类型
.nek/SYSTEM.md替换本项目的系统提示词
.nek/APPEND_SYSTEM.md追加本项目的系统提示词
.nek/extensions/项目扩展
.nek/skills/项目 Skills
.nek/prompts/项目提示词模板
.nek/themes/项目主题
.nek/plans/Plan 模式写出的计划文件

以上除 plans/ 外都要在信任项目后才加载。项目里的 AGENTS.md 不在 .nek/ 里，而是放在项目目录本身，见 项目指令。

合并规则 ​

  • settings.json：项目设置覆盖用户设置；对象类型的设置（如 compaction）递归合并；资源列表（skills、prompts 等）合并。
  • nek.yaml：先读用户级，再读项目级覆盖。
  • mcp.json：项目里的同名服务器替换用户级的条目（只写开关字段时只覆盖开关）。
  • agents/：同名时项目 > 用户 > 内置。
  • 有几项只能在用户级设置：defaultProjectTrust、httpProxy、cacheWarming。

系统提示词文件 ​

  • SYSTEM.md 整体替换默认的系统提示词。nek 会在它前面保留一句身份说明（“You are working inside nekcode, a terminal coding agent.”）。
  • APPEND_SYSTEM.md 在系统提示词末尾追加内容。
  • 项目级的同名文件作用于该项目。
  • 命令行也能临时指定：--system-prompt <文本或文件>、--append-system-prompt <文本或文件>（可重复）。

一般情况下优先用 AGENTS.md 写项目指令，它不会改动 nek 的基础提示词和工具说明。

数据目录与 pi 的关系 ​

nek 使用独立的数据目录，不读取也不迁移 ~/.pi/ 里的数据。从 pi 迁移时，可以手动复制需要的文件（例如 models.json、AGENTS.md、skills/、prompts/、themes/），把项目里的 .pi/ 改成 .nek/。凭据建议用 /login 重新登录。
